# Архитектура Harmonia — версия 0 (черновик)

Дата: 2026-11-08. Статус: черновик для обсуждения. Основано на решениях из `docs/PROJECT.md`
и пробных программах `docs/research/spike-01.md`, `spike-02.md`.

## 1. Общая картина

```
┌──────────────────────────── Harmonia.exe (C++, JUCE 9) ────────────────────────────┐
│  app      — запуск, окно, настройки, автосохранение, восстановление после сбоя     │
│  ui       — piano roll, плейлист, микшер, браузер, тема, горячие клавиши           │
│  core     — модель проекта: дорожки, клипы, ноты Harmonia, команды, undo           │
│  audio    — Tracktion Engine: транспорт, устройства, плагины, рендер, инструменты  │
└──────────────┬───────────────────────────────────────────────────┬─────────────────┘
               │ общая память + канал (M52)                        │ IPC (позже)
     ┌─────────▼─────────┐                               ┌─────────▼──────────┐
     │ plugin host       │  каждый плагин в своём        │ harmonia-ai (Rust) │
     │ (src/sandbox)     │  процессе — защита от падений │ стемы, поиск, ИИ   │
     └───────────────────┘                               └────────────────────┘
```

Правило зависимостей: `app → ui → core`, `app → audio → core`. `ui` не знает про Tracktion Engine напрямую —
только через интерфейсы `core`/`audio`. Так интерфейс не привязан к движку, а модель можно тестировать без окна.

## 2. Модули

| Модуль | Что делает | Зависит от |
|---|---|---|
| `core` | Обёртка над `tracktion::Edit`: проект, дорожки, клипы, **ноты Harmonia**, выделение, команды с undo, сохранение/загрузка. Без GUI. | Tracktion Engine (модель), JUCE core/data_structures |
| `audio` | Аудиоустройства (ASIO/WASAPI/CoreAudio), транспорт с «играть, когда готово», загрузка и окна плагинов, рендер в файл, встроенные инструменты, перевод свойств нот в MIDI/MPE. Упавшие плагины и их перезапуск — `audio::plugin_safety`. Пресеты плагинов (файлы, загрузка с undo) — `audio::presets`. Смены темпа по ходу песни — `core::tempo_changes`. Дубли аудиоклипа (запись по кругу, выбор) — `core::takes`. Цепочки эффектов в файлах — `audio::chains`. Заморозка дорожек — `audio::freeze`. Сэмплы на клавишах драм-машины — `audio/DrumSamples`. Прежние версии песни при сохранении — `core::backups`; звуковые файлы песни (каких нет, сбор в папку песни, поиск пропавших) — `core::song_files`. Список инструментов и эффектов для выбора, избранное и недавние — `audio::plugin_catalog`. Сэмплер (один звук нотами) — `audio::sampler`; звук в памяти для обоих — `audio::SampleData`. Пошаговый секвенсор (вид на ноты клипа) — `ui/stepseq`. MIDI Learn (CC → параметр, в песне) — `audio::midi_learn`; запись движения ручек в автоматизацию — `audio::automation::Writer`. | `core`, Tracktion Engine |
| `sandbox` | Плагины в отдельных процессах (решение 23): процесс плагина (`Host`, тот же exe с `--harmonia-plugin-host`), заместитель плагина для Tracktion (`RemotePlugin`), сторож зависаний, платформенное (общая память, сигналы, процессы) за `sandbox::platform`. | JUCE |
| `ui` | Компоненты JUCE. Свой слой отрисовки (кеш слоёв, упрощение при отдалении), тема (цвета, размеры — токены), система горячих клавиш со своим слоем ввода (левый/правый Shift и Alt). | `core`, `audio` (через интерфейсы), JUCE gui |
| `app` | Точка входа, главное окно, настройки, автосохранение, журнал, обработчик сбоев. | всё выше |
| `harmonia-ai` | Отдельная программа на Rust: разделение на стемы, индекс библиотеки, поиск по описанию. Общается с DAW по локальному каналу. Падение не влияет на DAW. | ONNX Runtime (`ort`) |
| `tests` | Модульные тесты (doctest — уже есть в Tracktion, MIT), тесты производительности (как пробная программа 2), тест самопроверки звука (как пробная программа 1). | все модули |

## 3. Потоки

| Поток | Что в нём | Нельзя |
|---|---|---|
| Главный (message thread) | Интерфейс, все изменения модели, undo | Долгие операции (> ~5 мс) |
| Аудиопоток (Tracktion) | Обработка звука по графу | Выделять память, блокировки, файлы, ИИ, ожидание GUI |
| Фоновые потоки | Сканирование, анализ, подготовка данных отрисовки, рендер | Трогать модель напрямую — только через сообщения в главный поток |
| Процессы `harmonia-ai`, `plugin host` | ИИ-задачи, плагины | — |

Изменения модели → Tracktion сам перестраивает граф воспроизведения асинхронно.
Tracktion останавливает воспроизведение, когда перестраивает подключения устройств (перезапуск звуковой карты,
появление MIDI-устройств). `audio::Transport` хранит намерение пользователя «играть» и продолжает с того же места,
пока не нажат Stop; без звуковой карты ждёт её («играть, когда готово»). Граф готовится при открытии проекта.

## 4. Модель нот (главное решение для piano roll)

Нота Tracktion хранит только высоту, начало, длину, velocity, release velocity, цвет и mute.
Для piano roll уровня FL нужно больше. Решение:

- **Источник правды — `tracktion::Edit` (дерево ValueTree).** Свою параллельную модель не заводим —
  иначе двойное состояние и рассинхронизация.
- **Узел ноты `NOTE` расширяем своими свойствами** (ValueTree это позволяет, Tracktion сохраняет их в файл):
  `hPan`, `hModX`, `hModY`, `hFinePitch` (центы), `hSlide`, `hPorta`, `hGroup`; позже `hRepeat` (note repeat —
  вместе с поведением). Цвет/канал ноты — родной атрибут Tracktion `c` (своего `hChannel` не заводим, чтобы не
  дублировать). Значения по умолчанию не пишутся — файл не раздувается.
- **`core::Note`** — значения ноты (обычная структура); **`core::NoteEditor`** — единственный путь правки нот клипа:
  каждое изменение идёт в undo и сразу копируется в связанные копии клипа (`core/ClipLinks`, атрибут `hLinkGroup`)
  в той же транзакции. Интерфейс работает только через них.
- **Воспроизведение:** встроенные инструменты Harmonia читают все свойства напрямую. Для сторонних плагинов
  свойства переводятся в MIDI: fine pitch и слайды → изгиб высоты на ноту (MPE pitch bend, Tracktion это умеет),
  Mod Y → MPE timbre (CC74), Mod X → MPE pressure или выбранный CC, панорама → CC10 в канале ноты (в MPE у каждой
  ноты свой канал). Если плагин не умеет MPE — работают только общие для канала значения. Детали — отдельное исследование.
- **Undo:** все правки — через `juce::UndoManager` Tracktion; один жест мышью = одна транзакция.

## 5. Проект на диске

Папка проекта: `Название.harmonia/` с файлом проекта (XML Tracktion Edit + наши свойства), папками `audio/`,
`samples/`, `renders/`, `backups/` (автосохранения). Формат файла версионируем с первого дня (`hFormatVersion`),
чтобы старые проекты открывались новыми версиями.

## 6. Интерфейс и отрисовка

- Свои компоненты JUCE и своя тема; никакого «веб-вида».
- Отрисовка через нашу прослойку: стартуем с программной (стабильные 60 к/с), Direct2D — когда уберём ограничение 30 к/с.
- Тяжёлые виды (piano roll, плейлист): кеш статичного слоя картинкой, поверх — курсор воспроизведения и наведение;
  при отдалении ноты склеиваются по пикселям.
- **Piano roll** (`src/ui/pianoroll`): `PianoRollModel` — клип, выделение, инструмент, привязка, буфер обмена
  и все команды (без отрисовки, тестируется без окна); `GridGestures` — поведение мыши в сетке нот;
  компоненты `NoteGrid`, `PianoKeys`, `TimeRuler`, `ControlLane` только рисуют общий вид (`View`: масштаб и прокрутка)
  и передают ввод. Привязка к сетке и операции над нотами — чистые функции в `core/Snap`, `core/NoteOps`.
  Сетка рисует только перерисовываемую полосу, поэтому курсор воспроизведения дешёвый даже при 20 000 нот.
- **Аранжировка** (`src/ui/arrangement`): `ArrangementModel` — дорожки, текущая дорожка и открытый в piano roll
  клип, выделение клипов (по ID, чтобы undo не оставлял висячих указателей), привязка, режим Clip/Song, луп и
  команды; `ArrangementGestures` — мышь (двигать, копии, края, удаление, рамка); компоненты `ClipArea`,
  `ArrangementRuler`, `TrackHeaders`, `Arrangement` только рисуют общий вид (`ArrangementView`) и передают ввод.
  Операции над клипами — в `core/Clips` (`move`, `setStart`, `setEnd`, `duplicate`, `remove`; MIDI и аудио),
  связанные копии — `core/ClipLinks` (только MIDI). Вид дорожки — `core/Tracks` (с инструментом или аудио,
  свойство `hTrackKind` в проекте): аудиоклипы живут только на аудиодорожках, MIDI — только на дорожках
  с инструментом. Звуковые файлы: `Project::addAudioClip` (клип ссылается на файл на месте),
  `ArrangementModel::importAudio` (куда класть), перетаскивание — `Arrangement` (`FileDragAndDropTarget`),
  волна — `ClipArea` (`te::SmartThumbnail` на клип, только видимая часть).
- **Редактор аудиоклипа** (`src/ui/audioeditor`, нижняя панель аудиодорожки вместо piano roll):
  `AudioEditorModel` — клип (`ArrangementModel::getFocusedAudioClip`: кликнутый или первый на дорожке), перевод
  секунд файла в доли песни и обратно (как рисует аранжировка: от начала файла в песне, со скоростью растяжения)
  и команды; `AudioEditorGestures` — мышь (края, фейды, громкость, клик, колесо); `View` — масштаб в секундах
  файла; `WaveformView` и `AudioEditor` (панель) только рисуют и передают ввод. Ручки фейдов и громкости —
  общие с аранжировкой (`ui/AudioClipHandles`: где они, что делает перетаскивание, как выглядят).
- **Запись звука:** `audio/AudioInputs` — готовность к записи и вход аудиодорожки (свойства дорожки
  `hRecordArmed`, `hRecordInput`) и назначение входов движка (`InputDeviceInstance::setTarget` +
  `setRecordingEnabled`) только готовым дорожкам. `audio::Transport::play` записывает (`TransportControl::record`),
  когда `recordsAudio` (в `MainComponent`: Rec включён и есть готовые дорожки); Stop — клипы одним шагом undo.
  Куда пишутся файлы — `HarmoniaEngineBehaviour::getFileForNewAudioRecording` → `Session::getFileForNewRecording`
  (`Project::save` задаёт `editFileRetriever`, чтобы записи шли к проекту).
  `ui/MainComponent` связывает: открытый клип → piano roll, текущая дорожка → инструмент, клавиатуры; что играет
  Play — `ArrangementModel::getPlayRange`. Файлы (новый/открыть/сохранить, экспорт `audio/Export`) — `app/MainWindow`,
  он владеет проектом и пересоздаёт экран при смене проекта; `MainComponent` зовёт их через `ui/FileCommands`.
  Формат экспорта — `audio/ExportFormat` (окно выбора `ui/ExportOptions`); MP3 кодирует система за `audio/Mp3Encoder`
  (Windows — Media Foundation, решение 24). Окно настроек — `ui/settings/SettingsPanel` (вкладки звука, MIDI,
  плагинов); всё, что там меняется, хранит `te::PropertyStorage` (свои ключи — у владельцев: `PluginScanner`,
  `Session`, `ExportFormat`).
- **Микшер и эффекты:** `audio/Effects` — цепочки эффектов (список плагинов дорожки: инструмент, эффекты,
  громкость/панорама, индикатор; у мастера только эффекты, громкость мастера — отдельный плагин после них);
  каждое изменение — один шаг undo. `audio/PluginControls` — ручки любого плагина (параметры Tracktion или
  свойства, которые встроенные эффекты хранят без параметров); по ним `ui/ParameterPanel` строит окно
  ползунков, если у плагина нет своего (`ui/PluginWindow`). `ui/mixer`: `Mixer` (полоски дорожек и мастер,
  следит за деревом проекта), `ChannelStrip`, `LevelMeter` (читает `te::LevelMeasurer`: дорожки — её
  `LevelMeterPlugin`, мастер — `masterLevels` текущего контекста воспроизведения, который бывает пересоздан).
  `MainComponent` показывает снизу piano roll или микшер (F7 / F9).
- **Правка аранжировки:** разрез (`core::clips::split` → `te::split`) и буфер обмена клипов
  (`ArrangementModel::copySelected / cutSelected / paste`: копии состояний `te::ClipCopy` и их смещения по
  дорожкам и долям; `core::clips::insertCopy` даёт новые ID и отвязывает от группы связанных).
  Предотсчёт — `te::Edit::setCountInMode` (настройка движка) через `audio::Transport::setCountIn`; работает,
  когда Play записывает звук (`TransportControl::record`).
- **Фейды и громкость аудиоклипов:** `core::clips::get/setFadeInBeats / FadeOutBeats / FadeShape / GainDb` поверх
  `te::AudioClipBase` (фейды хранятся в секундах, снаружи — доли). Ручки на клипе — одна геометрия
  `ArrangementGestures::getAudioHandles` для рисования (`ClipArea`) и мыши.
- **Посылы:** `audio/Sends` — возвратные дорожки (`core::tracks::Kind::fxReturn`: в конце списка дорожек,
  `Project::getTracks` их не отдаёт — аранжировка их не видит; `getReturnTracks`) с `te::AuxReturnPlugin` на
  своей шине первым в списке и посылы — `te::AuxSendPlugin` на той же шине после громкости дорожки. Эффекты
  (`audio::effects`) их не считают эффектами и ставят новые после aux return. Заглушённая дорожка не шлёт
  (`HarmoniaEngineBehaviour::shouldProcessAuxSendWhenTrackIsMuted`), возвратные — solo isolate.
- **Автоматизация:** `audio/Automation` (`audio::automation`) — линии ручек поверх `te::AutomationCurve`
  параметра (`AutomatableParameter::getCurve`): точки снаружи в долях песни и 0..1 диапазона ручки, внутри —
  как хранит кривая (время или доли). Ручки дорожки — громкость/пан (`VolumeAndPanPlugin`), уровень посылов
  (`AuxSendPlugin::gain`), параметры эффектов и инструмента. Воспроизведение и экспорт идут по кривым сами;
  при смене темпа точки переносит движок (`EditTimecodeRemapperSnapshot`). UI — `ui/automation`: жесты
  (`AutomationGestures`, без окна), полоса (`AutomationLane`), панель с выбором ручки (`AutomationPanel`,
  F8), горизонталь — общий `ArrangementView` аранжировки.
- **Ввод нот:** `ui/NoteInput` собирает ноты с клавиатуры компьютера (`ui/ComputerKeyboard`) и MIDI-клавиатур
  (`audio/MidiInputs`), даёт их услышать и во время записи пишет в клип через `core/NoteRecorder` (чистая логика:
  нажатия → ноты, круги, педаль; квантование). Место ноты — то, что человек слышал: `audio/PlaybackClock` сводит
  поток звука движка с часами и вычитает задержку вывода и плагинов. MIDI-клавиатуры играют инструмент дорожки
  силами движка (назначение входа на дорожку), клавиатура компьютера — через `NotePreview`. Клавиши компьютера
  читаются по скан-кодам (`ui/PhysicalKeys`, Windows), поэтому раскладка не важна.
- Горячие клавиши — настраиваемая таблица; свой опрос левого/правого модификатора (Windows: `GetKeyState(VK_LSHIFT)`,
  macOS: флаги устройства в событии клавиатуры).

## 7. Сборка, тесты, CI

- Корневой `CMakeLists.txt` + `CMakePresets.json` (Windows: MSVC + Ninja; macOS: arm64).
- Тесты: doctest; запуск `ctest`. Тесты производительности с порогами (например, «отрисовка 20 000 нот < 16 мс»).
- CI: GitHub Actions, сборка + тесты на Windows; macOS — позже. Учесть лимиты: у приватного репозитория
  бесплатных минут ограниченно, минуты macOS считаются в 10 раз дороже; у публичного — без ограничений.
